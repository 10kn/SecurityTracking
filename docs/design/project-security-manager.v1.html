Đề xuất cuối: Go + PostgreSQL + React tĩnh. Scanner chạy riêng. Collector tự xây chỉ bổ sung khi CI, agent hoặc cloud API chưa đáp ứng.

Còn lựa chọn Có dùng Dependency-Track hay gọi scanner/API trực tiếp cần được so sánh trong pilot.

Inventory

Server truyền thống và ECS đi hai đường thu thập

OS / HOST

Lấy phiên bản đầy đủ

/etc/os-release, uname -r, dpkg-query hoặc rpm. Giữ cả nguồn cài đặt và phiên bản package đầy đủ.

RUNTIME / CONTAINER

Phân biệt scope

PHP/Node trên host có thể khác trong container. Binary CLI cũng chưa đủ chứng minh runtime phục vụ ứng dụng là cùng bản.

FRESHNESS

Mất báo cáo là thiếu dữ liệu

Lưu collected_at và last_seen. Cảnh báo khi ngừng gửi; không suy diễn “không có rủi ro”.

Payload inventory minh họa từ session
{
  "asset_id": "project-a-prod-api-01",
  "environment": "production",

  "runtimes": [{
    "name": "php", "version": "8.4.27",

  }],
  "deployment": {
    "release": "release-123", "image_digest": "sha256:..."
  }
}

Schema đề xuất cho Hub; không phải CycloneDX SBOM gửi trực tiếp vào Dependency-Track. Giá trị chỉ là ví dụ, không xác nhận hiện trạng production.

Có thể lấy inventory qua Wazuh hoặc AWS Systems Manager thay cho collector tự xây. Với Fargate, tập trung vào image/container của ứng dụng; không giả định có quyền quản lý host bên dưới.

Phạm vi hệ thống

Không thay thế SAST, review phân quyền, kiểm tra cấu hình hạ tầng, đánh giá đường khai thác hoặc regression test sau nâng cấp. “Khớp phiên bản bị ảnh hưởng” chưa chứng minh ứng dụng có đường khai thác.

Response

Cảnh báo sớm trước, xác nhận ảnh hưởng khi có đủ bằng chứng

Mục tiêu watcher trong session là kiểm tra mỗi 15–30 phút, cần đo trong pilot. Nhịp báo cáo collector ví dụ mỗi giờ và sau triển khai cũng chỉ là cấu hình đề xuất, chưa phải SLA.

Operations

Giữ dịch vụ thường trực gọn, tách tải scan khỏi API

TÁI SỬ DỤNG

Inventory theo digest

Nhiều deployment dùng cùng artifact chia sẻ inventory và kết quả phù hợp. Khi advisory thay đổi, phân tích lại dữ liệu đã lưu.

GIỚI HẠN TẢI

Queue hấp thụ đợt scan

Giới hạn scan đồng thời. Tránh clone và build lại toàn bộ repository cho mỗi lần kiểm tra.

VÒNG ĐỜI DỮ LIỆU

Giữ bằng chứng cần dùng

Đặt retention cho log và kết quả thô. Tính cả database, dịch vụ phân tích và phút CI khi so sánh chi phí.

Chi phí chưa thể chốt bằng ngôn ngữ

Chưa có benchmark hoặc báo giá hạ tầng trong session. Cần đo CPU/RAM đỉnh, độ dài queue, thời gian phân tích, dung lượng dữ liệu và tổng chi phí hai phương án.

Inventory và scanner nhìn đúng host/container, không bỏ sót vì thiếu dữ liệu hoặc nhầm scope.
